# Final Fusion · Build and test

The host is a native macOS app. The Mac viewer is built with the host; the Go helper also builds the Windows viewer. The host creates a paired viewer for each user's own setup. This repo has no preconfigured relay or personal receiver file.

## Build

On a Mac, install the Xcode Command Line Tools, a macOS SDK with ScreenCaptureKit, and Go as specified in `Link/go.mod`. Install the Windows resource tool with `go install github.com/tc-hib/go-winres@v0.3.3`. Then:

```sh
export GO_TOOL="$(command -v go)"
export WINRES_TOOL="$(go env GOPATH)/bin/go-winres"
out="$(mktemp -d)"
SIGN_IDENTITY=- bash build.sh "$out"
app="$out/파이널 퓨전.app"
bin="$app/Contents/MacOS/StudioRemote"
```

This is a local development build. It uses ad hoc Mac signing and an unsigned Windows viewer; it is not an Apple-notarized or Windows-signed distribution. A user-provided signing identity can be selected with `SIGN_IDENTITY`. See [Relay/SETUP.md](Relay/SETUP.md) for the user's own Cloudflare setup.

## Check

```sh
codesign --verify --strict --deep "$app"
lipo -archs "$bin"
"$bin" --self-test
"$bin" --test-loopback
"$bin" --test-video
"$bin" --test-native-video
"$bin" --test-session "$out/session.png"
"$bin" --test-separated-transport
mkdir -p "$out/fixture"
"$bin" --test-export "$out/fixture"
FINAL_FUSION_LANGUAGE=ko FINAL_FUSION_PREVIEW_MODE=agent "$bin" --preview-ui "$out/preview"
(cd Link && go test ./...)
```

The native video and session tests use generated data and a local connection. Preview states include `connecting`, `exporting`, and `updating` via `FINAL_FUSION_PREVIEW_STATE`. Use the viewer generated by `--test-export` to preview the Mac viewer. These checks do not substitute for checking real receiving laptops.

## Find and fix a problem

- **Settings, activity indicators and preview:** `main.swift`, `Design.swift`, `UIPreview.swift`.
- **Mac viewer, screen fitting and shortcuts:** `Viewer.swift`, `ReceiverMode.swift`, `InputBehavior.swift`, `TrackpadGestures.swift`.
- **Host capture and input:** `Host.swift`, `VirtualDisplay.m`.
- **Pairing and update files:** `Pairing.swift`, `ReceiverUpdate.swift`.
- **Windows UI, direct and relay transport:** `Link/`, `Link/ui/`, `Wire.swift`, `Relay/`.
- **AI help and diagnostics:** `AgentSupport.swift`, `Link/ui/*-agent*.txt`.

For sharing, use `"$bin" --support-report-shareable` or copy the in-app AI help. Share only the needed details. The local `--support-report`, `--host-status`, and `--receiver-report` commands may show local paths, relay addresses, or other device details. Do not post their raw output.

Real receiver packages are private: the Mac package contains `Receiver.json`; Windows appends the same kind of data to its executable. Use fake packages for tests and screenshots. Host keys and configuration belong in the user's local application-support folder, never in this repository or an issue.
